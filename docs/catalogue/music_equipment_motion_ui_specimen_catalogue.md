# Music Equipment-Inspired Motion & UI Specimen Catalogue

A large catalogue of portable motion/UI artifacts inspired by physical
and software music equipment: mixing desks, synthesizers, drum machines,
pedals, samplers, turntables, DJ decks, modular synths, tape machines,
studio racks, tuners, audio interfaces, DAWs, MIDI editors, loopers,
launchpads, meters, scopes and live-performance systems.

> **Creative rule:** study the interaction grammar of music technology
> rather than cloning a particular manufacturer or product. Avoid
> proprietary logos, exact industrial designs, copyrighted panel
> artwork, branded knob layouts, trademarked device silhouettes,
> sample/audio assets or pixel-copy plugin interfaces. Use generic
> hardware geometry, original labels, deterministic synthetic signals
> and CSS/inline SVG visualisations.

This inspiration family is especially valuable because music equipment
makes **state physical**. Knobs remember values. Faders occupy
positions. LEDs latch. Meters decay. Cables show routing. Transport
controls explain time. Sequencers make schedules visible. The resulting
specimens can feel tactile without needing sound.

# Strong Software Mappings

-   **Mixer faders → multi-parameter control:** visible physical
    positions make configuration states easy to compare.
-   **Scene recall → workspace presets:** restore many settings at once
    with coordinated movement.
-   **VU meters → live system health:** throughput, CPU, queue depth,
    confidence and load can inherit meter behaviour.
-   **Peak hold → incident memory:** transient maxima remain visible
    after the live value has recovered.
-   **EQ → filter/query weighting:** draggable graph nodes make abstract
    weighting systems tangible.
-   **Compressor → rate limiting:** threshold and ratio communicate what
    happens when input becomes excessive.
-   **Noise gate → conditional trigger:** work begins only after a
    measurable threshold is crossed.
-   **Pedalboard → processing pipeline:** stages can be enabled,
    bypassed and reordered.
-   **Patch bay → data routing:** visible cables connect sources,
    transforms and destinations.
-   **Modular synth → workflow automation:** small modules and
    modulation routes create composable systems.
-   **Step sequencer → scheduled jobs:** cells on a rhythmic grid become
    recurring execution slots.
-   **Sampler pads → macro launcher:** pads become tactile shortcuts for
    commands and workflows.
-   **DJ cue points → timeline bookmarks:** saved moments support
    instant navigation through long processes.
-   **Crossfader → comparison/blending:** one control continuously
    trades prominence between two states.
-   **Tuner → target alignment:** below/above target becomes flat/sharp;
    exact alignment becomes centred.
-   **Loop ring → recurring process:** circular progress communicates
    the next repeat boundary.
-   **Transport controls → simulations/replay:** play, pause, record,
    loop and scrub are universal temporal controls.
-   **Automation lanes → parameter history:** editable curves explain
    and control values over time.
-   **Sidechain → dependencies:** activity in one system directly
    affects another.
-   **Rack startup → dependency sequencing:** services wake and shut
    down in safe order.
-   **Launchpad → deployment matrix:** queued, active and stopped clips
    map neatly to jobs or environments.
-   **Piano roll → schedule editor:** blocks have time, duration and
    lane/category.

# Suggested Original Visual Grammar

Keep the family manufacturer-neutral. A useful base palette:

-   chassis `#17191C`
-   panel `#25282D`
-   engraved text `#D7D9DC`
-   inactive LED `#3B3F45`
-   active signal `#78C68A`
-   warning `#E2B45B`
-   clip / destructive `#D85D57`
-   display blue `#7CB6D9`

Use colour primarily as **state**, not decoration. Hardware should
remain legible in near-monochrome form.

Controls should have frozen geometry: knob diameter, pointer angle,
fader travel, detents, LED segment count, meter decay, threshold
positions and display dimensions are part of the specimen contract.

# Playground Technical Contract

-   Prefer plain HTML + CSS; use tiny vanilla JS where controls, drag
    interactions, deterministic signal simulation or timeline state
    require it.
-   Must run inside `<iframe sandbox="allow-scripts">`.
-   Never require `allow-same-origin`, parent access, cookies/storage,
    navigation, fetch, WebMIDI, WebAudio, microphone access or external
    APIs.
-   Do not depend on actual audio input. Meter/scope demos should use
    deterministic pre-authored value sequences or mathematical signals.
-   No React/Vue/framework runtime inside specimens.
-   No external fonts, images, samples, audio, video or manufacturer
    assets.
-   Prefer `deps: ['none']`.
-   Inline SVG is allowed for original curves, meters, cables, waveforms
    and scope geometry.
-   Freeze exact control geometry, ranges, detents, timings, easing,
    meter attack/decay and numeric values.
-   Avoid runtime randomness. If a signal needs variation, use a fixed
    deterministic sequence.
-   Scaffold only the minimum host required: mixer strip, pedalboard,
    rack, deck, waveform editor, sequencer, patch bay, etc.
-   Honour both `prefers-reduced-motion` and
    `data-force-reduced-motion`.
-   Reduced-motion mode must preserve all parameter values and semantic
    state; animated meters/scopes should freeze to a representative
    static frame.
-   Looping animations such as meters, playheads, sequencers and
    metronomes must stop under reduced motion.
-   Replay/reset must clear intervals, animation frames, pointer state,
    temporary nodes and transient classes.
-   Keyboard operation should be included for interactive knobs, faders,
    pads and transport controls where practical.
-   Register specimens explicitly in `src/specimens/index.ts`.
-   Do not redesign catalogue chrome.
-   Acceptance criteria must be observable: exact fader position, exact
    number of lit meter segments, loop boundary, cable endpoints, knob
    angle, etc.

# Catalogue Thesis

Music equipment is one of the richest sources of software interaction
design because almost every abstract state is turned into something
**spatial, tactile or temporal**. A fader tells you where a value lives.
A VU meter tells you what is happening now. Peak hold tells you what
just happened. A patch cable tells you why one thing affects another. A
sequencer tells you when something will happen. A transport tells you
where you are in time.

For the Playground, the strongest music-equipment specimens should make
software feel **touchable, routable, measurable and performable**. The
goal is not to imitate a famous synthesizer or mixing desk. It is to
steal the deeper interaction trick: make invisible system behaviour
occupy a physical-looking place.
