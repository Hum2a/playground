# Newspaper & Editorial Motion / UI Specimen Catalogue

A large catalogue of portable motion/UI artifacts inspired by newspaper
production, editorial design, print journalism, magazines, copy desks,
live news, investigative documents, archives, data desks and physical
paper behaviour.

> **Creative rule:** this catalogue studies the visual and interaction
> grammar of editorial media rather than copying any specific
> publication. Avoid real newspaper mastheads, proprietary fonts,
> copyrighted article text, photography, logos or exact page layouts.
> Use fictional publication names, original headlines, abstract
> photography placeholders and generic editorial geometry.

Unlike many inspiration catalogues, this family can work beautifully
with almost no colour. The interesting material is hierarchy: type
scale, columns, rules, margins, paper, ink, correction, annotation,
chronology and information priority.

-   **Corrections → audit history:** revised information stays visibly
    connected to what changed.
-   **Redaction → permissions:** protected fields remain structurally
    present while their values are withheld.
-   **Margin notes → code/design review:** comments stay spatially
    attached to the exact content they discuss.
-   **Election results → live aggregation:** counts, thresholds and
    declared states fit elections, sports, voting and batch processing.
-   **Archive editions → version history:** builds, releases and
    snapshots become browsable historical issues.
-   **Paywall → feature/access gate:** preserve user context while
    restricting continuation.
-   **Reading progress → workflow progress:** a quiet hairline indicator
    works well for forms, documentation and onboarding.
-   **Print registration → reconciliation:** multiple distributed states
    visibly converge into agreement.
-   **Proof-to-final → approval workflow:** annotated draft becomes
    approved clean state.
-   **Live blog → incident/event log:** timestamped operational events
    appear as a continuously updating narrative.
-   **Contact sheet → asset review:** many candidates remain visible
    while one expands for inspection.
-   **Strict newspaper grid → dense enterprise UI:** hierarchy and rules
    can replace excessive cards and chrome.

# Suggested Original Visual Grammar

Keep the specimen family publication-neutral. A useful starting palette:

-   ink `#111111`
-   paper `#F2EFE7`
-   newsprint grey `#D8D3C8`
-   correction red `#B3261E`
-   editor blue `#315D7A`
-   highlighter `#E6D86A`

Use colour sparingly. Most effects should work in ink + paper alone.

Typography should be expressed through generic font categories or
locally available fallbacks rather than downloaded publication fonts.
Strong contrast between display serif, compact sans and mono/typesetter
metadata is enough to create the editorial hierarchy.

# Playground Technical Contract

-   Prefer plain HTML + CSS; tiny vanilla JS only for deterministic
    state, timing, keyboard, pointer, drag/drop or measurement.
-   Must run inside `<iframe sandbox="allow-scripts">`.
-   Never require `allow-same-origin`, parent access, storage,
    navigation, fetch or external APIs.
-   No React/Vue/framework runtime inside specimens.
-   No external photography, fonts, audio or proprietary publication
    assets. Use original CSS/inline SVG geometry and fictional copy.
-   Prefer `deps: ['none']`.
-   Freeze exact dimensions, column counts, type sizes, line heights,
    rule weights, timings, easing and thresholds.
-   Avoid runtime randomness.
-   Scaffold only the minimum editorial host required: front page,
    article teaser, document, copy desk, live blog, archive stack, etc.
-   Honour both `prefers-reduced-motion` and
    `data-force-reduced-motion`.
-   Reduced-motion mode must preserve hierarchy, disclosure state,
    reading order and keyboard usability.
-   Any ticker/crawl loop must stop under reduced motion and expose the
    full information statically.
-   Replay/reset must clear timers, temporary nodes, inline transforms
    and transient classes.
-   Preserve semantic reading order when visually rearranging columns or
    modules.
-   Register explicitly in `src/specimens/index.ts`.
-   Do not redesign catalogue chrome.
-   Acceptance criteria must describe observable layout/motion behaviour
    rather than subjective editorial vibes.

# Catalogue Thesis

Editorial interfaces have a different superpower from game and
entertainment UI: **they make hierarchy physical**. A more important
story becomes larger. A correction remains attached to the record. A
margin note sits beside the sentence it challenges. A breaking event
interrupts the page. A front page can be replated when priorities
change. Rules, columns and whitespace explain relationships before
animation does anything.

For the Playground, the strongest newspaper-inspired specimens should
make software feel **authored, prioritised, inspectable and
accountable**. Motion should behave less like decoration and more like
an editor physically reorganising information in response to new facts.
