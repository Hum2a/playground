## Shared quality bar (apply to every specimen)

For each improvement pass, require:

1. **One composition** that reads as a named software primitive (confirm, failover, dispatch…), not “Naruto HUD demo.”
2. **Palette family unique to its motif** (no default parchment/chakra five-pack unless that motif *is* mission paper).
3. **Frozen contract**: colours, phase timings, geometry (angles, counts, travel px), copy strings as `const`.
4. **Observable acceptance** with numbers; delete soft sandbox trailers as standalone criteria.
5. **Progressive motion that matches metaphor** (reconstruct / clip / stamp / streak) — not opacity fade as primary language.
6. **Reduced motion**: immediate final state that still communicates the outcome; keep both CSS triggers.
7. **Portable CSS**: edit only inside the specimen folder; sync `demo.style.txt` twin; no chrome tokens.
8. **Overlay hosts**: real `preview.scaffold` (relative + overflow) when the effect overlays content.
9. Recalibrate `intensity` (`subtle` → `graphic` for multi-phase/loud effects).
10. Strip visible checklist IDs (`NR // NR-090`). Prefer auto-play + `postMessage` restart over heavy Run/Replay chrome where the metaphor is a transition.

**Palette families** (assign once, then apply per specimen):

- **Seal lacquer** — deep ink, vermillion, ash paper
- **Clone ash** — charcoal, muted violet afterimage, paper white
- **Fire ember** — near-black, ember orange, soot grey
- **Water / wind** — cool cyan / steel edge (distinct from each other)
- **Mission paper** — warm paper, wax-seal red, ink
- **Sensor phosphor** — CRT/sensor green-blue on near-black (radar, scan, signature)

Reference quality: Dragon Ball measurement-overload (frozen sequence + hold); Persona fusion merge (travel/seam/scale acceptance).

## Execution protocol (each specimen)

1. Open folder under `library/naruto/<id>/`.
2. Implement HTML/CSS/JS changes; sync `demo.style.txt`.
3. Harden `contract.json` + `spec.md` + `entry.ts` (blurb, acceptance, intensity, scaffold, reducedMotionNote).
4. Preview in catalogue; verify reduced-motion force.
5. `npm run spec:check` (and build when touching many).
6. One commit per specimen (or per Wave 0 batch of 3): `Improve SPX-NNNN <title>` — why-focused.

Do **not** restyle to site chrome; do **not** invent new NR rows here — this is polish of shipped 50.
